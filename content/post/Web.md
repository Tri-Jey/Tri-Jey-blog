# Web安全
## 计算机网络基础
### 一.网络分层模型（OSI七层 & TCP/IP四层）
1. OSI七层（自上而下）：应用层 → 表示层 → 会话层 → 传输层 → 网络层 → 数据链路层 → 物理层
2. TCP/IP四层（实际互联网使用）：
- 应用层：HTTP、HTTPS、DNS、FTP、SSH
- 传输层：TCP、UDP
- 网络层：IP、ICMP
- 网络接口层：网卡、以太网、MAC地址
3. 分析：
Web漏洞属于应用层漏洞;端口属于传输层;IP属于网络层。
4. 攻击分层理解：
- 应用层：SQL注入、XSS、文件上传（Web安全主要研究层）
- 传输层：端口扫描、TCP劫持
- 网络层：IP欺骗、路由劫持
**重点区分：Web安全大多不关心底层网线、MAC，重点看应用层+传输层+网络层。**

### 二.MAC地址
1. MAC是网卡硬件地址，固化在网卡，长度48位（12位十六进制）。
- 作用：局域网内部通信寻址，只在同一个局域网生效，跨网段MAC无效。
2. 分析:
ARP攻击基于MAC欺骗；MAC地址可以软件伪造。MAC不能跨路由器传递。

### 三.IP地址（IPv4）
1. IPv4: 32位，点分十进制  A.B.C.D 。分为网络位+主机位，子网掩码区分。
- 分类：A/B/C/D/E类，日常只用A、B、C。
2. 私有内网IP（保留地址，公网路由不转发）：
- 10.0.0.0 ~ 10.255.255.255（/8）
- 172.16.0.0 ~ 172.31.255.255（/12）
- 192.168.0.0 ~ 192.168.255.255（/16）
**公网IP：全球唯一，互联网路由可达。**
3. 分析:
内网主机可以主动访问外网；外网不能直接主动访问内网主机。拿到内网一台主机后，可横向渗透，内网横向移动是渗透重要环节。

### 四.子网掩码、网段、网关
1. 子网掩码用来区分IP的网络位和主机位，判断两台机器是否在同一局域网。
2. 网关：内网主机访问外网的出口设备（一般是路由器）。同一网段通信不需要网关；跨网段必须交给网关转发。
3. 分析:
渗透中信息收集：判断目标网段，规划内网扫描范围；网关是内网攻击重点目标。

### 五.ARP协议（地址解析协议）
1. 作用：已知IP，查同一局域网内对应的MAC地址。
2. ARP广播发送请求，单播返回结果；结果保存在本机ARP缓存表。 
3. 分析:
ARP欺骗：伪造ARP响应，篡改缓存。中间人劫持局域网流量，监听同一局域网电脑流量。

### 六.ICMP协议
1. 网络层控制报文协议，不携带端口。常用工具 ping 基于ICMP。
2. ping作用：测试两台主机网络连通性；TTL值判断操作系统。
3. 分析:
防火墙经常封禁ICMP，ping不通≠主机不存在；攻击者用ICMP隧道做数据外传。

### 七.传输层：TCP协议
1. TCP面向连接、可靠传输；有确认应答、重传、拥塞控制。
2. 核心：三次握手建立连接，四次挥手断开连接。
3. TCP有端口号（1~65535）。
**三次握手简单流程：**
1. 客户端发SYN（请求连接）
2. 服务器回复SYN+ACK（同意连接）
3. 客户端回复ACK，连接建立
**四次挥手：**
1. 客户端FIN：我不再发数据
2. 服务端ACK：收到关闭请求
3. 服务端FIN：服务端也没有数据发送
4. 客户端ACK，连接关闭
**分析:**
1. Web服务HTTP/HTTPS都跑在TCP之上；端口扫描就是向目标IP发送TCP握手包，判断端口是否开放。
2. SYN洪水是DDOS攻击，消耗服务器连接资源。

### 八.传输层：UDP协议
1. UDP无连接、不可靠；没有握手挥手，开销小，速度快。无确认重传。
2. 典型应用：DNS、视频直播。
3. 分析:
UDP端口扫描难度更高；DNS放大DDOS利用UDP无连接特性。

### 九.端口概念（TCP/UDP端口）
1. 端口范围：1 ~ 65535。
- 公认端口 1–1023：系统常用服务
- 注册端口1024–49151：普通应用
- 动态端口49152–65535：客户端临时端口
2. 常见服务端口：
- 80：HTTP（TCP）
- 443：HTTPS（TCP）
- 22：SSH远程管理
- 21：FTP文件传输
- 53：DNS（UDP为主）
- 3306：MySQL数据库
3. 分析
- 开放端口 = 攻击面。nmap等扫描器探测开放端口，根据端口判断运行服务版本，查找对应漏洞。
- 防火墙可以封禁端口阻断访问。

### 十.DNS协议（应用层）
1. 功能：域名 ↔ IP 的解析。
2. 域名分级：根域 . → 顶级域com/org → 二级域名baidu.com → 子域名 xxx.baidu.com
3. 解析顺序：浏览器缓存 → hosts文件 → 本地DNS缓存 → 递归DNS服务器 → 根DNS → 权威DNS。
- hosts文件：本地静态映射，优先级高于DNS解析。
4. 分析:
**安全风险：**
- DNS劫持：篡改解析结果，跳转到钓鱼网站
- 子域名枚举：收集目标所有子域名，扩大攻击面
- DNS隧道：把数据隐藏在DNS请求中外传，绕过防火墙

### 十一.NAT 网络地址转换
1. 路由器NAT：多个内网IP共用单个公网IP上网。内网主机访问外网，路由器改写数据包源IP。
2. 分为源NAT（内网访问外网）、目的NAT（端口映射，外网访问内网服务）。
3. 分析:
家用内网就是NAT环境，外网无法直连内网主机；端口映射会暴露内网服务，带来安全风险；反弹shell就是利用内网主动向外建立连接，绕过NAT限制。

### 十二.路由原理
1. 路由器查看目标IP，匹配路由表，转发数据包，跨网段通信。数据包经过多个路由器一跳一跳转发。
2. 分析:
路由劫持可篡改流量；渗透内网需要看懂路由表，寻找可达网段。

### 十三.防火墙基础
1. 防火墙根据五元组（源IP、目的IP、源端口、目的端口、协议）控制数据包放行/阻断。
2. 分为主机防火墙（Windows防火墙）、网络防火墙。
3. 分析:
防火墙可以封禁IP、端口；但防火墙大多无法拦截应用层Web漏洞（SQL注入/XSS），因为数据包是合法HTTP。

### 十四.五元组概念
1. 五元组：源IP、源端口、目的IP、目的端口、协议(TCP/UDP)
2. 互联网识别一条网络连接的唯一标识。
3. 分析
防火墙、WAF、流量日志都依靠五元组记录网络会话，排查攻击流量。

### 十五.网络代理
1. 代理服务器作为中间人。
- 正向代理：客户端上网代理（翻墙代理）
- 反向代理：Nginx，用户访问反向代理，代理转发请求到后端多台Web服务器。
2. 分析:
反向代理（Nginx）是Web最常见架构；X-Forwarded-For（XFF）头就是反向代理用来传递真实客户端IP；攻击者伪造XFF头欺骗后端获取权限。

### 十六.数据包传输完整链路（访问网站全过程） 
1. 输入域名，查DNS得到服务器IP
2. 本机判断目标IP不在局域网，发给网关
3. 路由转发数据包到达服务器
4. TCP三次握手，建立客户端 ↔ Web服务器TCP连接​
5. 客户端发送HTTP请求（应用层数据）
6. 服务器处理，返回HTTP响应数据包
7. 客户端接收数据，浏览器渲染页面
8. TCP四次挥手断开连接
**分析:**
底层网络负责把数据包送到服务器；漏洞发生在应用层的HTTP数据处理环节。网络层安全和Web应用安全是两件事。
 
### 十七.会话、连接的区别
1. TCP连接：传输层，是底层通信通道。
2. 应用层会话（Cookie/Session）：应用层，是业务登录身份。
**一条TCP连接可以承载多次HTTP请求（HTTP长连接Keep-Alive）。** 
3. 分析:
TCP连接断开 ≠ 用户登出；Session失效才代表业务会话结束。

### 十八.Keep-Alive（TCP长连接）
1. HTTP Keep-Alive：TCP连接复用，一次TCP握手后，连续发送多个HTTP请求，不用反复握手，提升效率。
2. 分析：
渗透爆破请求、批量请求会复用长连接；某些DOS攻击利用长连接耗尽服务器连接。

### 十九.负载均衡
1. 多台后端Web服务器，前端反向代理分发流量，分担压力。
2. 分析：
负载均衡环境下直接拿到的IP是代理IP，后端真实服务器IP隐藏；抓包看到的IP不一定是真实业务后端。

### 二十.CDN内容分发网络
1. CDN在全国各地节点缓存静态资源。用户访问域名，调度到就近CDN节点，不直接访问源站。
2. 分析
CDN隐藏真实源站IP；WAF很多集成在CDN上；扫描到的IP只是CDN节点，不是真实服务器。

### 二十一.常见网络攻击类型（网络层/传输层，区分于Web应用漏洞）
1. DDoS：洪水攻击（SYN洪水、UDP洪水）消耗服务器带宽/连接资源
2. ARP欺骗：局域网中间人劫持
3. IP欺骗：伪造源IP数据包 
4. 分析
**注意：**这类属于网络层攻击，和SQL注入/XSS这种应用层Web漏洞不是一类。Web安全学习要分清。

### 二十二.网络日志基础
1. 防火墙日志、路由器日志记录五元组、数据包放行拒绝；Web服务器日志记录HTTP应用层请求。
2. 分析
入侵溯源，攻击者被发现后，运维通过网络日志追溯攻击来源IP、请求行为。

### 二十三.主机网络基础：网卡、回环地址127.0.0.1
1. 127.0.0.1 本地回环地址，本机访问本机服务，数据包不经过物理网卡。
2. localhost 等价127.0.0.1。
3. 分析
SSRF常访问127.0.0.1读取本地服务；开发测试本地web服务使用。

### 二十四.网络抓包基础概念
1. 抓包工具（Wireshark）抓取网卡上所有数据包，能看到网络层、传输层、应用层原始流量。
2. Wireshark看底层TCP/IP；Burp只抓HTTP/HTTPS应用层流量。
3. 分析
Wireshark用来分析TCP握手、ARP、ICMP；Burp专注Web应用HTTP攻击

## HTTP协议
### 一.基础概念
1. HTTP：应用层、基于TCP、明文、无状态、无连接
2. 默认端口：80，HTTPS：443（TLS加密）
3. 无状态：服务器不记用户，靠 Cookie/Session/Token 维持登录

### 二.HTTP四大版本区别
1. HTTP1.0：短连接，一次请求断一次
2. HTTP1.1：持久连接、Host头、缓存完善（最常用）
3. HTTP2：二进制、多路复用、更快
4. HTTP3：基于UDP QUIC，防阻塞

### 三.URL补充
1. 结构： 协议://[user:pass@]host:port/path?query#fragment 
2. #fragment ：锚点，不会发给服务器，浏览器本地用
3. URL编码：特殊字符转义，注入、绕过经常用到， 空格=%20 ， &=%26 
4. 路径遍历： ../  属于URL路径部分，文件包含/目录穿越漏洞常用

### 四.HTTP报文结构（重中之重） 
1. 请求报文：请求行 → 请求头 → 空行 → 请求体
2. 响应报文：状态行 → 响应头 → 空行 → 响应体
- GET 无请求体
- POST/PUT 有请求体
- 空行  \r\n\r\n  是头和body分界线，没有空行服务器解析失败

### 五.九大请求方法
1. GET：查数据，可注入
2. POST：提交数据，上传、登录、注入
3. HEAD：只返回头，扫描目录用
4. PUT：上传覆盖文件（高危！可写shell）
5. DELETE：删除文件（高危）
6. OPTIONS：查看服务器支持方法、探测CORS
7. TRACE：回显请求（会产生XST漏洞，必须关闭）
8. PATCH：局部更新
9. CONNECT：隧道代理
#### 方法覆盖： X-HTTP-Method-Override: PUT ，后端支持时可以用POST伪装成PUT
#### 区分： OPTIONS  预检请求，CORS跨域的时候浏览器自动发
#### 安全/幂等
- 安全：只读不改（GET、HEAD）
- 幂等：多次请求结果一样（GET、PUT、DELETE）

### 六.常用状态码
1. 2xx 成功
- 200 正常访问
- 201 Created：创建资源成功（PUT/POST新建）
- 204 No Content：成功但无返回内容
2. 3xx 重定向
- 301 永久重定向
- 302 临时重定向
- 304 走缓存
- 307/308：重定向保持原请求方法（302会把POST变GET）
3. 4xx 客户端错误
- 400 Bad Request：报文畸形、参数非法
- 401 未登录
- 403 登录但无权限
- 404 不存在
- 405 方法不允许
- 413 Payload Too Large：请求体太大，上传限制
- 429 Too Many Requests：限流、防爬虫/WAF拦截
4. 5xx 服务器错误
- 500 代码报错（注入常见）
- 502/503 服务挂了
- 504 超时（延时盲注常见）

### 七.请求头
1. 最常改的请求头：
- Host：指定访问站点（虚拟主机）
- User-Agent：伪造浏览器、绕过WAF
- Referer：伪造来路、绕过防盗链
- Cookie：登录凭证、越权、会话劫持
- X-Forwarded-For(XFF)：伪造IP
- Content-Type：控制传参格式（上传漏洞关键）
- Authorization：账号密码认证
2. 请求头新增
-  Accept ：告诉服务器我能接收什么类型
-  Accept-Encoding ：gzip压缩，抓包看到乱码很多是这个原因
-  If-Modified-Since / If-None-Match ：协商缓存
-  Content-Length ：请求体长度；和  Transfer-Encoding: chunked  互斥
-  Origin ：跨域请求里携带，和Referer类似，CORS校验用

### 八.响应头 
1. 响应头安全
- Server / X-Powered-By：泄露版本（不安全）
- Set-Cookie：Cookie三个安全属性
- HttpOnly：防XSS偷Cookie
- Secure：只HTTPS携带
- SameSite：防CSRF
2. 响应头新增
-  Access-Control-Allow-Origin ：CORS核心头，配置不当造成跨域漏洞
-  Location ：3xx跳转地址，容易出现开放重定向漏洞
-  Allow ：OPTIONS返回，列出允许的请求方法
-  Content-Security-Policy (CSP) ：安全头，防御XSS
-  X-Frame-Options ：防点击劫持
-  X-XSS-Protection ：旧浏览器XSS防护头

### 九.POST传参格式
1. urlencoded（普通表单，最常见）
2. multipart/form-data（文件上传专用）
3. json（接口渗透常用）
- raw：自定义格式（xml、二进制等）
- 注意：GET也可以带body，只是规范不推荐，部分后端会解析（小众绕过技巧）

### 十.Cookie & Session & Token（核心）
1. 
- Cookie：客户端存储，可篡改
- Session：服务器存储，靠SessionID识别用户
- Token/JWT：前后端分离，无状态登录
- Session一般存在文件/Redis/数据库；SessionID大多放在Cookie里
- Cookie属性补充： Domain 、 Path  控制Cookie发送范围，越权相关
- JWT结构：header.payload.sign，签名用来防篡改，但是密钥泄露就可以伪造
2. 常见漏洞
- 会话劫持（偷Cookie）
- 会话固定（伪造SessionID）

### 十一.缓存机制
1. 强缓存：不访问服务器，本地读取； Cache-Control: max-age 、 Expires 
2. 协商缓存：和服务器对比是否更新； Last-Modified 、 ETag 
3. 缓存投毒：利用缓存机制污染页面，属于Web高阶漏洞

### 十二.HTTP vs HTTPS 
1. HTTP：明文、可抓包篡改劫持
2. HTTPS：HTTP+TLS加密、防窃听、防篡改、验证服务器身份
3. HTTPS不是新协议，只是HTTP跑在TLS之上
4. 证书作用：身份认证；TLS握手完成后才开始传HTTP明文（加密后的）
5. 中间人攻击MITM：HTTP极易劫持；HTTPS需要伪造证书+受害者信任证书才可以劫持
6. HSTS：强制浏览器只用HTTPS访问，防止降级攻击（http downgrade）

### 十三.报文&传输小知识点
1. Keep-Alive ：长连接，一条TCP连接多次HTTP请求
2. Transfer-Encoding: chunked  分块传输：不知道body总长度的时候用，可用来绕过WAF检测
3. HTTP管线化：一次性连续发多个请求，不用等上一个响应，1.1支持但很少开

### 十四.同源策略（和HTTP强绑定，Web安全基石） 
1. 同源：协议、域名、端口三者全部相同
2. 同源策略限制：AJAX跨域读响应；但img、script、iframe标签默认允许跨域加载
3. 绕过方式：CORS、JSONP（老接口）
 
### 十五.HTTP安全漏洞对应关系
1. 参数可控 → SQL注入、XSS
2. 允许PUT → 任意文件上传
3. 允许DELETE → 任意文件删除
4. TRACE开启 → XST
5. 无HttpOnly → Cookie劫持
6. 无CSRF校验 → 跨站请求伪造
7. 可伪造XFF/Referer → IP伪造、绕过
8. 主机头攻击：Host头可控，后端拿Host拼接内容
9. HTTP走私（HTTP Request Smuggling）：CL/TE、TE/TE冲突，CTF考点
10. HTTP慢速攻击：Slowloris，慢慢发送报文耗尽连接，属于DoS
11. 目录枚举：HEAD/GET探测404/200，配合状态码扫目录

## Web信息收集（目录/信息泄露）
1. 目录扫描（目录爆破）
- 原理：网站服务器存在可访问的目录、后台路径，通过字典批量请求，根据响应状态码判断是否存在。
- 核心：web服务器默认会对目录返回列表（目录浏览/目录遍历），属于配置失误。

2. 敏感文件泄露
- 开发、测试、备份遗留的文件没有删除，直接放在web根目录，外网可访问。

3. 区分两个容易混淆的名词
- 目录浏览（Directory Listing）：打开目录直接列出里面所有文件（apache、nginx开启autoindex）
- 目录遍历（LFI本地文件包含）：是漏洞， ../ 跨目录读取服务器任意文件，不属于信息收集扫描，是漏洞利用，不要搞混。

4. 常见状态码含义
-  200 OK ：资源存在，可访问
-  301/302 ：重定向
-  403 Forbidden ：目录存在，但是禁止访问（有价值，说明路径真实存在）
-  404 Not Found ：不存在
-  401 Unauthorized ：需要账号密码认证（后台管理页）

5. 常用扫描工具 
- dirsearch（python写，最常用）
- gobuster（go语言，速度快，推荐）
- dirb（kali自带）
**命令示例：**
- gobuster dir -u http://xxx -w 字典.txt 
- python3 dirsearch.py -u http://xxx 

6. 高频敏感目录
-  /admin 、 /admin.php 、 /manage 、 /manager  后台管理
-  /phpmyadmin 、 /phpMyAdmin  数据库管理面板
-  /backup 、 /bak 、 /data 、 /db  备份目录
-  /test 、 /dev 、 /debug  测试开发目录
-  .git 、 .svn 、 .hg  版本控制目录（源码泄露）
-  /robots.txt  网站爬虫协议（重点！开发会在这里写不希望爬虫访问的路径）

7. 高频敏感文件泄露
- 备份类文件：
 xxx.bak 、 xxx.backup 、 xxx.old 、 xxx.~ 、 xxx.zip 、 xxx.tar.gz 、 xxx.sql （数据库备份）
**例： index.php.bak  直接下载源码**

8. 版本控制泄漏 
-  .git/  目录泄露：可以拿到完整源代码
-  .svn/  subversion源码泄露
-  .DS_Store  mac系统文件索引，泄露目录文件名

9. 配置文件
- config.php 、 config.inc.php 、 web.config 、 nginx.conf 、 httpd.conf 
里面经常包含数据库账号密码、密钥。

10. 日志文件
 access.log 、 error.log ，记录访问记录、参数、报错信息
11. 其他
 robots.txt 、 readme.md 、 install.php （安装页面，没删可以重装）、 env （.env，存密钥）

12. robots.txt
- 访问地址：http://目标/robots.txt
- 作用：给搜索引擎爬虫看的协议，Disallow 后面写禁止爬虫访问的路径
- 安全意义：相当于开发者主动告诉攻击者敏感路径
- 注意：robots.txt只是协议，爬虫/攻击者可以无视限制直接访问

13. 信息收集其他辅助手段（和目录扫描配套）
- 源码查看：F12看页面源码，注释里面经常出现路径、账号、接口、测试地址
- 前端JS文件：.js文件里泄露接口地址、密钥、后台路径​
- 子域名收集：oneforall、subfinder（属于信息收集，但不属于目录扫描）
- 备案、whois、DNS记录（外围信息收集）

14. 风险&危害（简答题考点） 
- 拿到源码 → 代码审计，找漏洞
- 获取数据库备份文件 → 直接拖库，拿到账号密码
- 找到后台地址 → 尝试爆破、弱口令登录
- 拿到配置文件 → 数据库账号、API密钥泄露

15. 修复方案 
- 关闭web服务器的目录浏览（autoindex关闭）
- 上线前删除所有备份文件、测试文件、.git、.svn、install安装文件
- 敏感配置文件放在web根目录之外，外网无法直接访问
- 备份文件统一放到内网，不要放在web站点内
- 后台管理目录增加IP白名单、强认证、验证码

16. **注意事项：** 
- 目录扫描必须拿到授权，无授权扫描属于违法
- 403≠没用，403代表路径真实存在，是重要线索
- 区分：目录浏览（配置失误） VS 文件包含漏洞（代码漏洞）
- 不要只依赖工具，robots.txt、页面源码是低成本优先检查点
